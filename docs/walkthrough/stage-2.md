# Разбор этапа 2: демо на VPS

## 1. Что сделано

- **Runbook** `docs/DEPLOY.md`: выбор VPS, настройка сервера, первый деплой, обновление и откат, ручной бэкап, диагностика.
- **Проверка сервера** `tools/check_connectivity.py`: достижимы ли Telegram, YandexGPT, Google, Яндекс Диск и SMTP.
- **Профиль бота** `config/bot_profile.yaml` + `tools/setup_bot_profile.py`: имя, описание и «О боте» одной командой.
- **Политика конфиденциальности** `docs/privacy_policy.md` — черновик по таблице 12.4 ТЗ.
- Ротация логов Docker, чтобы диск сервера не заполнился.

Кода бота этап не меняет: это эксплуатация. Деплой выполняет владелец — доступа к серверу и боевому токену у разработчика нет.

## 2. Карта файлов

| Файл | За что отвечает |
|---|---|
| `docs/DEPLOY.md` | Пошаговая инструкция и чек-лист приёмки |
| `tools/check_connectivity.py` | TCP и TLS до внешних сервисов; запускается системным `python3`, без uv и секретов |
| `tools/setup_bot_profile.py` | Читает YAML, проверяет лимиты Telegram (64/120/512), показывает, к какому боту обращается, применяет после подтверждения |
| `config/bot_profile.yaml` | Тексты профиля |

| `docker-compose.yml` | Добавлена ротация логов (`max-size 10m`, `max-file 3`) |

## 3. Путь деплоя

1. На сервере `python3 tools/check_connectivity.py` — доступен ли `api.telegram.org`.
2. `git clone`, `mkdir data secrets`, `chown 1000:1000 data` (контейнер работает не под root).
3. `.env` с правами 600 и **боевым** токеном; `docker compose up -d --build`.
4. При старте `main.run()` применяет миграции Alembic, затем запускается polling.
5. Docker каждые 30 секунд запускает `app.healthcheck`: если файл heartbeat устарел, контейнер получает статус `unhealthy`.
6. `restart: unless-stopped` и `systemctl enable docker` поднимают бота после перезагрузки сервера.

## 4. Что изучить

- Docker Compose на сервере: `up -d --build`, `ps`, `logs`, `restart`, тома, права на файлы (uid в контейнере и на хосте).
- Основы безопасности Linux-сервера: вход по SSH-ключу, `ufw`, непривилегированный пользователь.
- Telegram Bot API: `setMyName`, `setMyDescription`, `setMyShortDescription`; @BotFather.
- Сокеты и TLS в стандартной библиотеке Python (`socket`, `ssl`).

## 5. Вопросы для самопроверки

<details><summary>1. Почему у бота нет открытых входящих портов и зачем тогда нужен файрвол?</summary>

Бот сам опрашивает Telegram (long polling), поэтому входящие соединения ему не нужны. Файрвол оставляет открытым только SSH и закрывает остальное на случай, если на сервере случайно запустится сервис с портом.
</details>

<details><summary>2. Что произойдёт, если запустить боевой токен локально, пока бот работает на сервере?</summary>

Telegram отдаёт обновления одному получателю: оба процесса получат `TelegramConflictError` и будут терять сообщения. Поэтому у dev-бота и боевого бота разные токены (ADR-12).
</details>

<details><summary>3. Почему каталог `data/` нужно отдать пользователю с uid 1000?</summary>

Контейнер работает не под root. Каталог, созданный на сервере от другого пользователя, для него недоступен на запись, и SQLite не откроет файл БД.
</details>

<details><summary>4. Почему бэкап SQLite делается через `backup()`, а не копированием файла?</summary>

В режиме WAL часть данных лежит в отдельных файлах `-wal` и `-shm`. Простое копирование `bot.db` может дать несогласованную копию, а `sqlite3.Connection.backup()` копирует целостное состояние без остановки бота.
</details>

<details><summary>5. Как узнать, что бот завис, хотя контейнер запущен?</summary>

По статусу `unhealthy`: healthcheck проверяет свежесть файла heartbeat, который обновляет задача в том же цикле событий. Если цикл завис, файл устаревает.
</details>

## 6. Что упрощено и почему

- Деплой ручной (`git pull && docker compose up -d --build`): автодеплой из CI в бэклоге ТЗ.
- Алертов об ошибках пока нет (FR-38 — этап 5): сбой виден в логах и по статусу контейнера.
- Бэкапы ручные до этапа 5.
- Аватар ставится вручную через @BotFather: Bot API для этого не используется.
- Черновик политики — техническое описание, не юридический документ; вопрос об уведомлении Роскомнадзора остаётся владельцу (ТЗ, 16.12).
- Скрипты `tools/` — отдельные утилиты, поэтому в `mypy app` не входят; их проверяют `ruff` и тесты.
